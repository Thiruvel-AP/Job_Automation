## ISSUE 001: Jobs with "closed" status are not recognized as finished, causing infinite loop

**Severity:** high. The user runs `careerops live` and the same jobs appear every time, never making progress.

### What happens

1. During discovery/shortlist, job ads are fetched and placed in the inbox (`data/jds/inbox/`).
2. User approves ads via `careerops shortlist`, which moves them to `data/jds/approved/<date>/`.
3. User runs `careerops live --max 10`. The `Live` class reads approved files via `shortlist.approved_files()`.
4. For each job, `live` calls the `tailor` hook, which runs `pretailor.run()`.
5. `pretailor.run()` performs a liveness check. If the posting is closed on the employer's board, it sets the job status to `"closed"` and calls `_drop()`.
6. `_drop()` moves the job's JD file from the **inbox** to `jds_done/closed/`. However, the file being processed by `live` is in the **approved** folder, not the inbox. So `_own_files()` doesn't find it, and the file stays in the approved folder.
7. Back in `live._advance()`, the job status is `"closed"`. This status is not explicitly handled, so it falls through to the `else` clause (line 953-954) which just returns the status.
8. In `live._one()`, the status `"closed"` is checked against the `FINISHED` tuple (line 58). `"closed"` is **not** in `FINISHED`.
9. Since the status is not in `FINISHED`, `_finish_file()` is not called, so the JD file is not moved out of the approved folder.
10. On the next `careerops live` run, the same file is found in the approved folder and processed again. Infinite loop.

### Expected

A job with status `"closed"` should be treated as finished:
- The JD file should be moved to `jds_done/closed/` (with a `.reason.txt` file).
- The job should not be processed again on subsequent runs.
- The live report should show the job as `closed` with the liveness reason.

### Root cause

Two related issues:
1. In `pretailor.py`, `_drop()` only looks for JD files in the inbox (`decided.inbox_dir(settings)`). It doesn't check the approved folder where `live` actually reads files from.
2. In `live.py`, the `"closed"` status is not in the `FINISHED` tuple, so `_finish_file()` is never called for closed jobs. The file remains in the approved folder.

### Fix direction (for the implementing model)

**Option A (minimal, in live.py):**
- Add `"closed"` to the `FINISHED` tuple in `live.py` (line 58).
- In `_advance()`, explicitly handle `"closed"` status: move the file to `jds_done/closed/` using `decided.move_file()` and return `"closed"`.
- This ensures `live` itself handles the file movement, regardless of what `pretailor._drop()` did.

**Option B (in pretailor.py):**
- Modify `_own_files()` to also search the approved folders (`decided.approved_dirs(settings)`).
- This makes `_drop()` work correctly when the file is in the approved folder.

**Recommendation:** Option A is safer because `live` is the command that owns the file at that point. `pretailor` runs during tailoring and shouldn't assume where the file came from. `live` should be the one to move the file when it decides the job is finished.

### Files to change
- `careerops/apply/live.py`: Add `"closed"` to `FINISHED`, handle it in `_advance()` to move the file.
