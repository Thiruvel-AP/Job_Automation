# Plan for fixing "closed" status loop in careerops live

## Objective
Fix the infinite loop where jobs with status "closed" are reprocessed on every `careerops live` run.

## Root Cause Analysis
1. `pretailor._drop()` only moves files from the inbox, but `live` processes files from the approved folder.
2. `live.FINISHED` tuple doesn't include "closed", so `_finish_file()` is not called.
3. The file stays in the approved folder and gets reprocessed.

## Implementation Steps

### Step 1: Add "closed" to FINISHED tuple in live.py
- Location: `careerops/apply/live.py`, line 58
- Change: Add `"closed"` to the `FINISHED` tuple

### Step 2: Handle "closed" status explicitly in _advance()
- Location: `careerops/apply/live.py`, in `_advance()` method around line 953
- Add an `elif st == "closed":` branch before the final `else` clause
- In this branch:
  - Move the JD file to `jds_done/closed/` using `decided.move_file()`
  - Write a `.reason.txt` file with the closure reason
  - Return "closed"

### Step 3: Write a test for the fix
- Location: `tests/apply/test_live_closed_status.py` (new file)
- Test that a job with status "closed" is processed once, file moved to jds_done/closed/, and not reprocessed on subsequent runs.

### Step 4: Run existing tests to ensure no regression
- Run `pytest tests/apply/ -v` to check apply tests
- Run `pytest tests/ -k "live" -v` to check live-related tests
