## Context
On 2026-11-24 LSEG's Workday job (`lseg.wd3.myworkdayjobs.com`, `manual:1d576f2fd4a5`) ended "no application form; apply by hand".
The run recorded a `form_not_found` row in `data/live/submit_failures.csv` and the job became `ready_not_submitted`.
The real situation: Workday puts a "Create Account / Sign In" step before any application form. The pipeline must never create an account or sign in.
The correct outcome is therefore the existing **account-required** outcome. That means:
- status `manual_apply_account_required`
- no failure row
- the apply pack ready and the listing opened for the user

`careerops/apply/live.py:_account_required` already supports this outcome; nothing maps Workday to it.

Two code paths, both found in the code, turn the wall into `FORM NOT FOUND`:
1. **Plan-first path** (`careerops/apply/planned.py` ~L116-125, used when `cli` passes a `planner`, which matches the message the user saw).
   It calls `formscan.reach()` without an agent, so the Workday "Apply" button is never pressed. `reached.ok` is False, and the code prints `FORM NOT FOUND` and counts a failure.
2. **Form-agent path** (`careerops/apply/assist.py` ~L646-653, for vendors other than Greenhouse, Lever and Ashby).
   The agent stops with `need_user: "a sign-in page: the agent never signs in or creates an account"` (`formagent.py:735` / `:888`).
   Then `problem = None if reached.outcome == "reached_form" else f"FORM NOT FOUND {direct}"` throws that reason away.

Hard rules kept throughout: never sign in or create an account, nothing typed on a sign-in page, no third attempt, Workday is never auto-submitted (`apply.kinds` already excludes it), no network or LLM in tests, no real `settings.yaml` in tests.
